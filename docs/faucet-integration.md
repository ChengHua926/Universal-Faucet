# Faucet CLI Integration

## 1. Scope

This repo owns only the user CLI and local XMRig process.

```text
drip
  -> local Ethereum identity
  -> generated XMRig config
  -> bundled XMRig
  -> faucet Stratum endpoint
  -> faucet HTTP API for status/vouchers
```

No backend, Stratum gate, accounting DB, contract, bridge, or swap logic lives
here.

## 2. Faucet API Used

The CLI is wired to the faucet backend shape in `../faucet`.

```text
GET  /pool
GET  /miner/:addr
GET  /onion
GET  /state/:addr
POST /voucher
POST /restore
```

`addr` is the local Ethereum address generated by `drip identity`.

## 3. Status Mapping

`drip status` reads:

```text
/pool         -> upstream connection, pool hashrate, active miners, total work
/miner/:addr -> owed atomic XMR, voucher watermark, shares, work, last share
/onion        -> advertised onion/API hints when available
local files   -> miner PID and cached voucher
```

The CLI does not derive accounting locally. It displays faucet-owned accounting.

## 4. Voucher Mapping

`drip checkpoint` calls:

```http
POST /voucher
{ "user": "0x<addr>", "amount": null }
```

Expected response fields:

```text
user
cumulative_amount
marginal
signed_at
signature
earned_cumulative
last_voucher_cumulative
on_chain_claimed
```

The local cache stores one voucher:

```text
$DRIP_HOME/voucher.json
```

Rule: keep the highest cumulative voucher only. `drip restore` replays that
cached voucher to `POST /restore`.

## 5. Stratum Mapping

XMRig uses the local Ethereum address as both Stratum username and rig ID.

```text
url     = config.mining_pool_url
user    = local Ethereum address
pass    = x
rig-id  = local Ethereum address
tls     = config.mining_pool_tls
sni     = true for rofl.app pool hosts
socks5  = config.tor_socks5, when set
```

Users do not install or run XMRig manually.

## 6. ROFL / Tor Behavior

The production Stratum endpoint is direct TLS to ROFL:

```text
DRIP_POOL_URL=stratum+ssl://p3333.m269.opf-mainnet-rofl-55.rofl.app:443
```

For `rofl.app` hosts, `drip` emits `sni = true` in the generated XMRig pool
config. Unsupported raw `rofl.app` URLs without `stratum+ssl://` are rejected.
Fallback paths:

```text
DRIP_POOL_URL=<operator-clearnet-relay>:3333
DRIP_POOL_URL=<onion-stratum-host>.onion:3333
DRIP_TOR_SOCKS5=socks5://127.0.0.1:9050
```

The production HTTP API is:

```text
DRIP_API_BASE_URL=https://p8080.m269.opf-mainnet-rofl-55.rofl.app
```

## 7. How To Test Without Tor

Mock faucet integration:

```bash
cargo test -p drip-cli --test faucet_api_e2e
```

Local profile and config generation:

```bash
export DRIP_HOME=/private/tmp/drip-play
cargo run -p drip-cli -- identity \
  --api-base-url https://p8080.m269.opf-mainnet-rofl-55.rofl.app \
  --pool-url stratum+ssl://p3333.m269.opf-mainnet-rofl-55.rofl.app:443
cat /private/tmp/drip-play/config.json
```

XMRig launch/config lifecycle:

```bash
cargo run -p drip-cli -- start --threads 1 --voucher-interval-seconds 300
cat /private/tmp/drip-play/xmrig-config.json
tail -n 50 /private/tmp/drip-play/xmrig.log
cargo run -p drip-cli -- stop
```

If no Stratum server is listening on `127.0.0.1:3333`, XMRig will run but log
connection failures. That still verifies CLI packaging, config, PID, and log
lifecycle.
